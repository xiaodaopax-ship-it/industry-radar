# Industry Radar

> Sector → segment → leaders & emerging companies → research shortlist. A single-file HTML dashboard built from SEC EDGAR and Yahoo Finance data, inspired by Peter Lynch's "fast grower" checklist. **Research tool, not investment advice.**

一个按"行业整体分析 → 细分领域拆解 → 龙头与新兴公司 → 研究机会清单"组织的看板。用 SEC EDGAR 和 Yahoo Finance 的公开数据，按彼得·林奇"快速增长股"的思路筛选，最后生成一个离线可打开的 HTML 页面。

**这是研究工具，不是投资建议。** 页面上的"机会""风险""结论"都是按数据规则自动生成的，用来决定先研究谁，不能代替对业务、竞争和管理层的判断。

## 看板结构

| 步骤 | 内容 |
|---|---|
| ⓪ 全市场热度 | 全部美股申报公司按 SIC 大类 / 4 位行业分组：营收加权增速、增速中位数、增速 ≥20% 占比、加速占比、利润率变化；标出本工具已覆盖的行业，用来发现下一个值得配置的行业 |
| ① 行业总览 | 行业判断与需求证据、行业 ETF 对比大盘、细分环节市值树图 |
| ② 细分拆解 | 环节"增长 × 估值"象限图、环节一览、环节内公司市值占比树图 |
| ③ 龙头分析 | 每个环节手动配置的龙头（可跨美股、台股、日股、韩股）：增长、利润率、估值、EPS 实际与预期、下季预期、一年走势 |
| ④ 新兴机会 | 增速 × 毛利率气泡图、研究优先池 Top 5、候选表（可按环节、市场、股价区间、结论筛选）、评估卡 |
| ⑤ 机会清单 | 按环节汇总"先研究谁"，全部行业的研究优先池，可导出 CSV |

**评估卡**（龙头和新兴公司共用同一种版式）：一句话介绍 → 综合结论（数据面 + 综合面）→ 增长 / 盈利 / 估值 / 财报 vs 预期四个指标块 → 机会与风险（业务层面、数据层面分开列）→ 六维综合评估 → 因子雷达图、52 周价格区间与目标价、林奇清单 → 下一步要验证的问题和研究笔记。

**六维综合评估**：业务与护城河、客户与集中度、管理层、行业形势、产品与创新、风险。每个维度有两层：

- **调研判断**：来自 `config/research/<代码>.json`，每条判断都附出处（年报、季报、财报新闻稿、电话会、监管公告）。`status` 为 `draft` 的是未经人工审核的调研草稿，页面会明确标出。
- **申报原文摘录**：`python -m radar research` 自动从 SEC 申报里摘出业务描述、提到客户占营收比例的原句、竞争段落、风险因素小标题、近一年高管变动公告（8-K 5.02），并从 XBRL 算出研发费用占营收比例；海外公司摘 Yahoo 的业务描述和高管名单。这一层只摘原文，不做判断。

仓库里已经附带 20 家研究优先池公司的调研草稿（美股 16 家，台湾、韩国 4 家），用作示例；它们是某一时点的草稿，使用前请自行核对。

内置十四个行业：AI 基础设施与半导体、医药与医疗、能源与电力、软件与网络安全、工程建设与专业承包、工业机械与航空零部件、支付与金融软件、券商、交易平台与放贷科技、油气开采、油服与炼化、金属、矿业与煤炭、航运与邮轮、保险与保险经纪、银行、REIT（房地产投资信托）。券商、保险、银行和抵押贷款 REIT 用单独的金融类评估口径（见下文"方法"）；油气、金属矿业煤炭和航运的所有环节标为周期，不进研究优先池、不显示 PEG，只用来观察数据；REIT 的环节设了 `"peg": false`（净利润含大额折旧，行业看 FFO / AFFO，本工具不采集），不显示 PEG。资产管理公司、空白支票公司（SPAC）、特许权使用费和专利授权公司不在覆盖范围。行业、环节、龙头、门槛都在 `config/` 里配置，可以自行增加。

`deep-dive/intel/` 是一个单公司深度看板示例（Intel：公司事件、财报与预期、行业层信号、分析结论），从龙头卡片可以直接跳转。

## 快速开始

需要 Python 3.9+，只用标准库，不需要安装依赖。

```bash
git clone https://github.com/xiaodaopax-ship-it/industry-radar.git
cd industry-radar

# SEC 要求在请求头里提供联系方式
export SEC_USER_AGENT="industry-radar you@yourmail.com"        # Windows PowerShell: $env:SEC_USER_AGENT="..."

python -m radar fetch    # 抓取数据并生成 site/index.html（首次约 30~60 分钟，之后有缓存）
python -m radar build    # 只用最近一次快照重新生成页面，不联网，几秒钟
python -m radar research # 为研究优先池、龙头和有调研文件的公司摘录申报原文（10-K、8-K、XBRL），然后重新生成页面
python -m radar heat     # 抓取全市场行业热度（SEC，首次较慢，有缓存），然后重新生成页面
python -m radar valuation # 现金流估值输入（SEC companyfacts / Yahoo、一致预期营收、10 年期国债），按公司缓存可续跑，约 10 分钟，然后重新生成页面
python -m radar quality  # 价值通道：SEC XBRL frames 取全部报送公司近 5 个财年的营收、净利润、经营现金流、资本开支、分红、回购、股东权益、商誉、现金与有息负债（约 120 次请求，已结束年份缓存 30 天），通过门槛的公司再取 Yahoo 行情，保存 data/quality_<ts>.json，然后重新生成页面
python -m radar.smoke    # 美股数据层自检（价值通道规则、全市场速查与页面条目一致）
python -m radar ledger   # 估值台账：按默认参数给每家公司追加一条记录到 data/ledger/us_ledger.jsonl（只追加，重复运行不重复记），然后重新生成页面
```

然后用浏览器打开 `site/index.html`。

页面导航与备注：左侧栏列出全市场热度、PEG 筛选和全部行业（点行业切换并跳到 ①，当前行业下有 ①–⑤ 步骤链接），顶部的"公司快速跳转"输入代码或公司名回车即可打开该公司的评估卡；窄屏（< 1100px）时侧栏收进左上角"☰ 导航"。右侧"备注 (n)"打开备注面板，评估卡和 PEG 表每行都有"＋备注"按钮（自动关联公司）。备注只保存在当前浏览器的 localStorage（键 `industry-radar-notes-v1`），不写进页面文件，重新构建不会丢；换浏览器或清理浏览器数据前用面板底部的"导出 JSON"备份，"导入 JSON"按备注 id 合并（同一条保留更新时间较新的版本）。

对比池：评估卡、龙头卡、新兴表、PEG 筛选和机会清单每行都有"＋对比"，最多 30 家，保存在 localStorage（键 `industry-radar-basket-us-v1`）。"评分排序"只在池内做相对排序：标准口径（营收同比、增速变化、毛利率、毛利率变化、营业利润率、增速调整后市销率、稀释、财报超预期）和金融口径（营收同比、税前利润率及变化、ROE、市净率、稀释）分组计算组内百分位，按可调权重加权平均；周期环节不参与评分；数据异常的维度不计分；覆盖维度不到一半标"数据不足"排在后面。股价、PEG、分析师目标价和结论标签只展示、不计分。分数只反映所选几家的相对位置，不是买卖建议。

单公司深度看板：

```bash
python deep-dive/intel/build.py            # 生成 site/deep-dive/intel/
python deep-dive/intel/build.py --offline  # 用已有快照重新生成
```

## A 股看板（独立）

A 股的数据来源、行业分类、财报口径和风险事件都和美股不同，所以单独一条流水线、单独一个页面 `site/cn/index.html`（主看板顶部有入口），规则互不影响。

```bash
python -m cn fetch   # 东方财富数据中心 + 巨潮资讯，保存 data/cn/snap_<ts>.json，并抓取评估卡所需的个股资料（首次约 25 分钟）
python -m cn build   # 离线生成 site/cn/index.html
python -m cn cards   # 只重新抓取评估卡的个股资料（同一快照已抓过且没失败的字段直接复用）
python -m cn ranges  # ② 全部筛选公司的 52 周前复权最高 / 最低，保存 data/cn/ranges_<ts>.json（串行、缓存 1 天、可续跑，约 1236 次请求，冷启动约 40 分钟）
python -m cn holders # 跟踪机构（北向 HKSCC、汇金、证金、社保、养老）在前十大流通股东里最近 5 个季报期的持股，保存 data/cn/holders_<ts>.json（全市场按股东查询，约 140 次请求）
python -m cn valuation # 现金流估值输入：近 5 个财年 + 半年报的经营现金流 / 资本开支 / 营收、最新资产负债表净现金、中国 10 年期国债收益率，保存 data/cn/valuation_<ts>.json（全市场查询，约 170 次请求）
python -m cn ledger  # 估值台账：按默认参数给 ② 每家公司追加一条记录到 data/cn/ledger/cn_ledger.jsonl（只追加，同一快照重复运行追加 0 条，不联网），然后重新 build
python -m cn quality # 价值通道输入：全市场近 5 个完整财年的营收、归母净利润、加权 ROE、经营现金流、资本开支、权益、有息负债、商誉 + 现金分红，保存 data/cn/quality_<ts>.json（已结束财年缓存 30 天）
python -m cn forward # 前向跟踪：台账标签之后的股价表现（相对同一起点全部公司中位数），写 data/cn/ledger/cn_forward.json（不联网）
python -m cn.smoke   # 数据层自检
```

估值台账（`python -m cn ledger`，只展示，不计分）：台账记录的是模型在默认参数下的输出，用来对比数据变化带来的估值变化；不是目标价，不是买卖建议；方法未回测。每条记录和同一公司上一条比较股价、基准估值、基准相对现价、隐含增速、一致预期，并把基准估值变化按 营收基数 → FCF 利润率 → 起始增速 → 净现金与股本 → 参数 归因。页面：评估卡里的台账子块（最新结论、股价 vs 基准走势和熊–牛区间、逐期记录表）、对比池"台账：本期变化"列、全局"估值台账 · 本期变化"（只有一期时显示"首次记录 …；下次每周更新后显示变化"）。
- 规则标签：`cn/ledger.py` 的 `TAG_RULES` / `tag_input()` / `tags()`（新记录记账时存进 `tags`）；页面的 `lgTags` 对同一压缩记录逐行镜像，所以已有记录不改写也有标签，两边必须一致。分组：变化幅度（基准变化 ±2 / ±5 / ±15%；FCF ≤ 0 看需要的利润率 ±2 / ±5pt）、估值位置（基准相对现价 ±15 / ±50%，现价低于熊 / 高于牛情景）、组合信号（基本面改善·价格未跟、价格先行、基本面转弱、预期上修 / 下修、差距收窄 / 扩大、口径切换、标签变化、风险门禁变化）、注意（一次性收入、增速截断、爬坡假设、周期、估值≤0）。标签按固定阈值机械生成，描述模型输出和数据变化，不是买卖信号；方法未回测。
- 筛选（台账分节顶部，纯前端，即时）：搜索（代码 / 名称）、行业、范围（40 张评估卡 / 全部 / 只看对比池）、估值方式、FCF 口径（含周期）、标签（任一）、估值位置区间（%）、变化方向（只有一期时不可用）。结果表 n / N 家、可排序、点代码跳转；变化最大两张表也按筛选。
- 全市场速查（页面顶部“全市场速查”，左侧“公司快速跳转”也会搜到）：快照里每一只有行情的 A 股（约 5500 只）都能查到，显示股价、市值、PE / PB、年初至今营收与净利润、毛利率、现金流 / 净利润，以及**没进入 ② 的全部原因**（营收增速 < 20%、规模不足、金融类、ST、无最新财报、无可比同比，一只股票可以同时有多个原因）和是否在价值通道里（不在时列出没过的门槛）。页面顶部按原因计数，之前不计数的“增速不足”现在也计入。速查只做定位和说明，没进入 ② 的公司没有风险门禁、估值和台账。
- 价值通道（`python -m cn quality` + `cn/quality.py`，页面“价值通道”分节）：和 ② 并列的第二个入口，不要求高增长。用最近 5 个完整财年（年报口径）判断：ROE 至少 4 年有数据、中位数 ≥ 10%、最低 ≥ 5%；自由现金流（经营现金流 − 资本开支）为正 ≥ 4 年；5 年经营现金流合计 / 归母净利润合计 ≥ 0.8；最近财年营收不低于 4 年前；有息负债 / 归母权益 ≤ 0.8；商誉 / 归母权益 ≤ 30%；年初至今盈利、营收不低于 ② 的规模下限、非 ST、非金融。通过的公司在通道内按 6 项百分位等权排序：ROE 中位数、最低 ROE、现金转化、FCF 收益率（5 年平均 FCF / 总市值）、盈利收益率（1/PE）、股息率（最近财年税前现金分红合计 / 总市值，来源 RPT_SHAREBONUS_DET）；周期行业只列出不排名。另列“现价隐含增速 vs 过去 4 年营收复合增速”（同一套现金流估值引擎反推，FCF 利润率取近 3 年平均，折现率 rf + 5%），只描述现价包含的假设，不进入得分。银行、保险、券商需要不同模型，暂未覆盖。排序没有回测，不是买卖建议；不进入 ③、基本面 / 交易标签、⚠ 数和对比池评分。
- 前向跟踪（`python -m cn forward`，`cn/forward.py` 调用与美股相同的 `radar/forward.py` 统计；页面在台账分节下方，构建时计算）：每条台账记录是一个起点（标签按当前阈值从该条记录重算），之后第 1 / 4 / 13 / 26 / 52 周的台账记录给出股价涨跌，减去同一起点全部公司涨跌的中位数（等权，不是指数；沪深300 未抓取），同行业 ≥ 5 家时另算相对同行业。股价是快照的不复权价、不含分红；前后总股本变化超过 25%（疑似送转 / 拆股 / 增发）的样本剔除并计数。不回填历史；起点 < 4 个或公司 < 20 家标“样本不足”；样本重叠、不独立、未做显著性检验。只描述发生了什么，不说明规则有效，不是买卖信号。

现金流估值（情景参考，只展示，不计分）：评估卡有"现金流估值（情景参考）"块，对比池有"Base 估值 vs 现价""隐含增速"两列（也进 CSV）。在页面里计算：TTM 营收 × 历史平均 FCF 利润率（近 3 年；周期行业近 5 年），起始增速（评估卡用一致预期 EPS 年化增速作营收增速代理，否则近 3 年营收 CAGR，再否则年初至今同比，截断到 −10% ~ +40%）10 年线性衰减到永续增速，加净现金后除以总股本；熊 / 基准 / 牛三情景、反向 DCF（现价隐含的起始增速和 FCF 利润率）、折现率 × 永续增速敏感性表。⑤ 顶部"估值参数"可改无风险利率（默认取中国 10 年期国债收益率）、ERP、永续增速（不超过无风险利率）和情景幅度，立即重算，保存在浏览器（键 `industry-radar-dcf-cn-v1`）。基准 FCF 利润率 ≤ 0 的公司只显示"需要的 FCF 利润率"。情景估值参考，不是目标价，不是买卖建议；不进入任何评分、标签、⚠ 数或排序。

FCF 利润率口径（"估值参数"里的"FCF 利润率口径"，默认"自动"；每张评估卡的估值块里还可以单独给这家公司设定口径、爬坡年数 N 和稳态利润率 T，"清除单独设定" / "清除全部单独设定"，存在同一个 localStorage 键的 `co` 里；"恢复默认"只重置全局参数）：
- 近 3 年平均（原来的做法，周期行业近 5 年）、最近财年、TTM（(TTM 经营现金流 − TTM 购建长期资产) ÷ TTM 营收，由半年报推算，经营现金流季节性强）、利润率爬坡：m_t = m_start + (T − m_start) × min(t / N, 1)，t = 1…10，终值用 m_10；m_start = TTM（可用且没有触发一次性收入时），否则最近财年；N（默认 5 年）和 T（默认 15%）是用户设定，不是数据得出。爬坡情景：熊 T × (1 − 幅度)、牛 T × (1 + 幅度)，折现率和增速情景不变。
- 疑似一次性收入（任一即触发）：(a) TTM 营收 > 1.5 × 最近财年营收；(b) 最近半年报（年初至今）营收 > 最近整财年营收；(c) 仅评估卡：一致预期明年 EPS < 今年预期 × 0.7（≥ 3 家机构，两年都 > 0）。触发时自动口径和爬坡起点都不用 TTM，卡片写"疑似一次性收入，未外推：…"；手动选 TTM 时仍用并提示。例：688331 荣昌生物 2026 H1 营收 58.5 亿 > FY2025 全年 32.5 亿，一致预期 EPS 2026E 7.68 → 2027E 1.25。
- 自动：周期行业 → 多年平均（从不用 TTM / 爬坡）；否则 TTM 存在、未触发、TTM > 近 3 年平均且 FY2023 < FY2024 < FY2025 → TTM；否则近 3 年平均 ≤ 0 且 FY2025 利润率高于 FY2024 → 爬坡；其余 → 近 3 年平均。所选口径缺数据时回退到近 3 年平均并注明。卡片总是并列近 3 年平均和 TTM，相差 > 10pt 时提示一次性因素，爬坡时列出逐年利润率路径。
- FCF ≤ 0（只给需要的利润率）的判断看实际路径的终点：平均 / 财年 / TTM 看 m0，爬坡看 T。反向 DCF 在爬坡下固定路径求 g0，隐含利润率改为"需要的稳态 FCF 利润率"（对 T 线性求解）。敏感性表、价格轴、对比池两列和 CSV 用同一条路径。Python 镜像：`cn/valuation.py` 的 `choose_basis` / `margin_path` / `one_off_guard` / `eps_drop` / `ramp_required` / `dcf_case`（`python -m cn.smoke` 校验，规则改动两边必须同步）。

机构动向（只展示，不计分）：② 筛选新增"机构"和"近 12 个月"（新进前十或增持 / 新进前十 / 增持 / 减持或跌出前十 / 最新期在前十）筛选，可与标签筛选组合（如 基本面支撑 + 香港中央结算 + 新进前十或增持）；② 表格和对比池有"机构动向"列，展开明细和评估卡有逐季持股表，③ 有"基本面支撑 × 机构动向"计数表（点数字套用 ② 筛选）。数据来自前十大流通股东（季报，披露有滞后）：香港中央结算有限公司是陆股通（北向）名义持有人，汇总所有境外投资者、含指数被动资金，不代表单一机构判断；掉出前十不等于清仓；早期股数已按送转调整。跟随机构持仓不是经过验证的选股信号，不是买卖建议。不进入任何评分、标签、⚠ 数或排序。

股价与 52 周区间（只展示，不计分）：② 筛选表、展开明细、③ 优先级、对比池和评估卡显示现价、52 周最高 / 最低区间条和区间位置 %。区间是前复权口径（与现价可比）；本机 push2his K 线接口几乎全部断连，所以用数据中心日收盘价按分红 / 送转除权除息换算成前复权，最高 / 最低是收盘价口径。52 周位置只说明股价在过去一年区间里的位置，不代表低估或高估；估值看 PE/PB 5 年分位。评估卡另显示机构目标价中位数：逐篇读取个股研报，近 180 天内每家机构取最新一篇带目标价的研报，≥ 3 家机构才显示（标"不是预测"），否则显示"机构目标价样本不足，不显示"；不使用一致预期汇总表的目标价上下限。价格、52 周位置、目标价都不进入任何评分、标签或排序。

内容：东财行业热度 → 新兴公司筛选（营收同比 ≥20%，现金流质量、商誉、质押、减持、解禁、监管类公告、估值分位、业绩预告逐项检查）→ 基本面 / 交易标签（规则透明，列出触发原因）→ 研究优先级 Top 30 → 个股评估卡。评估卡和优先级表另列 PEG 参考项（优先用机构一致预期 EPS 的两年年化增速，没有可用一致预期时用扣非年初至今同比；周期行业、PE ≤ 0、增速 ≤ 0 不显示；基数低、增速 > 100%、一致预期大幅下降时标为不可靠），**不参与排序和标签**。所有阈值在 `cn/build.py` 的 `RULES` 和 `cn/cards.py` 的 `CARD_RULES` 里，页面上也会列出。接口与字段说明见 `cn/SOURCES.md`。

## 方法

**新兴公司筛选**

1. 美国：从全部 SEC 申报公司里，按近 12 个月营收规模（默认 0.5 亿 ~ 30 亿美元）和最新季度营收同比（默认 ≥ 20%）预筛。
2. 海外：从 Yahoo 行业股票池里，按市值区间预筛，再取财务数据。
3. 按 SIC 代码（美国）或 Yahoo 行业（海外）加公司名称关键词，归到细分环节；可以在 `overrides` 里人工指定。
4. 每个环节可以有自己的门槛，例如公用事业的增长门槛是 10%。

**研究优先池**

先剔除周期性环节、缺市值、稀释超过 50%、亏损且现金撑不过 6 个季度、营收同比超过 300%（通常是一次性收入）的公司（金融类口径的门槛不同，见下）。剩下的按 10 个因子在本行业候选中的百分位排名取平均：增速、加速、毛利率、毛利率趋势、营业利润率、增速调整后的市销率、稀释、内部人净买入、分析师覆盖（越少越好）、EPS 超预期。

**权重相同，没有经过回测。** 排名只说明"数据面值得先看"，不代表会涨。

**PEG**

并排给两个 PEG（市盈率 ÷ 每股收益增速 %）和一个背离提示，阈值在 `config.json` 的 `flags.peg` 里。前瞻 PEG 依赖分析师对下一年的预期，历史 PEG 只看已经发生的增长；两者背离时（今年下滑、预期明年反弹，或者增长在放缓）单看一个容易误判。

- 前瞻（`d.pegf`）：Yahoo `earningsTrend` 的一致预期 EPS，本财年（`0y`）→ 下一财年（`+1y`）的增速，只有一年。要求 `+1y` 至少 `min_analysts`（3）家分析师、两个预期都大于 0。两个口径：PE TTM 口径 = 市盈率（市值 ÷ 近四季 GAAP 净利润）÷ 增速，用于判断；前瞻 PE 口径 = （股价 ÷ FY1 预期 EPS）÷ 同一增速，前瞻 PE 用按汇率换算后的 `mkt.eps_est["+1y"].yield_pct` 算（`100 / yield_pct`），所以预期币种和报价币种不同也没问题。
- 历史（`d.pegh`）：市盈率（TTM）÷ 过去 12 个月稀释 EPS 同比。美股来自 SEC XBRL frames（`us.hist_eps()`，存在 `eps_h`）：近四季净利润 = 上一年度 `NetIncomeLoss` + 今年已报季度 − 去年同期季度（CYxxxxQ4 frame 只覆盖约 1/5 的公司，第四季度用年度数字推算，和 `ni_ttm` 一样），一年前的四季同样算；除以四季平均稀释股数（`WeightedAverageNumberOfDilutedSharesOutstanding`，缺第四季度用年度加权平均，偏离中位数 3 倍以上视为单位错误剔除，不足 3 个季度就改用 TTM 净利润增速并注明）。年度净利润远低于前三季合计（推算第四季度 < −75% 前三季，如 SCHW 的年度 `NetIncomeLoss`）视为标签 / 单位错误，历史 PEG 不显示。龙头（Yahoo 取数）按 SEC 股票代码表映射 CIK，用同样的 frames；frames 缺季度时用该公司的 `companyconcept`（先 `NetIncomeLoss`，填不满两个窗口时缺的期间用 `ProfitLoss` 补）按“年度 + 年初至今 − 去年同期年初至今”算，最新 10-Q 还没进 XBRL 时用上一季并注明。只有年度数据的公司（日本）沿用最新财年净利润同比；Yahoo 季度口径（台湾、韩国）只有约 5 个季度，不显示；只交 20-F / 40-F 的公司（如 TSM）没有 us-gaap 数据，不显示。
- 不显示：TTM 亏损、增速 ≤ 0（历史：“过去 12 个月 EPS 同比 x%，不为正”）、一年前 TTM 亏损、标准口径的周期性环节、`sectors.json` 里设了 `"peg": false` 的环节（任何口径；原因写在 `peg_why`，例如 REIT）。金融类的周期环节（券商、加密、抵押贷款与产权保险）照算，加提示。
- 不可靠（显示但不参与判断和排序）：增速超过 `growth_unreliable_pct`（100%）；基数 EPS 不到股价的 `min_eps_yield_pct`（0.5%；前瞻看本财年预期 EPS，历史看一年前的 TTM EPS）。
- 背离（`d.peg_div`，评估卡里一行 ⚠，表格里 ⚠ 悬停看原因）：前瞻 ≤ `good_max` 而历史 EPS 增速 ≤ 0；前瞻 ≤ `good_max` 而历史 > `div_hist_rich`（2）；历史 ≤ `good_max` 而前瞻 > `div_hist_rich`；本财年预期 EPS 比上一财年实际（Yahoo `yearAgoEps`）低 `fy0_drop_pct`（10%）以上。
- 用在哪里：判断用前瞻（PE TTM 口径）。只有前瞻可靠且 ≤ `good_max`、历史 ≤ `rich_min` 或因非负面原因算不出（不是增速 ≤ 0）、并且没有背离时，才算“偏便宜”（清单估值项 ✓、机会里写一条，高市销率也不再单独算偏贵）；前瞻 > `rich_min` 算偏贵（不变）；前瞻 ≤ `good_max` 但有背离时估值项为“·”，不下结论，并在“要验证”里加一个问题。金融类估值排序因子：可靠且没有背离的前瞻 PEG，否则市净率。没有一致预期时：日本等年度口径沿用历史 PEG 判断（不变），美股季度口径的历史 PEG 只作参考。标准口径的排序因子仍是增速调整后的市销率，不用 PEG。
- 局限：Yahoo 一致预期是非官方汇总，常是调整后 EPS，而市盈率和历史增速用 GAAP 净利润；上一财年实际 EPS 也来自 Yahoo；frames 按日历季度对齐，非日历财年有错位，缺一季就算不出；GAAP 净利润含一次性项目（递延所得税资产确认等）；一年的增速噪声大。

**现金流估值（情景参考，不是目标价，不是买卖建议）**

评估卡里的“现金流估值”、PEG 筛选的“反向 DCF 隐含增速 vs 基准增速”列和对比池的“Base 估值 vs 现价”“隐含增速”列，**只展示，不进入评分、因子、结论、PEG 分层和对比池评分**。输入由 `python -m radar valuation` 取到 `data/valuation_<时间>.json`（每家公司缓存在 `data/cache/val/`，`valuation.cache_days` 天内不重取，中断后重跑会续上；`--refresh` 全部重取），`build` 自动读最新一份；计算在页面 JS 里（`dcfEngine`、`dcfReverse`、`riEngine`），参数在页面的“估值参数”里改，保存在 localStorage（键 `industry-radar-dcf-us-v1`），默认值在 `config.json` 的 `valuation.defaults`。

- 数据：SEC 申报公司用 companyfacts：经营现金流 `NetCashProvidedByUsedInOperatingActivities`（缺时 `…ContinuingOperations`）、资本开支 `PaymentsToAcquirePropertyPlantAndEquipment`（缺时 `PaymentsToAcquireProductiveAssets`、`PaymentsForCapitalImprovements`），营收按 `revenue_tags`；最近 5 个财年 + TTM（上一财年 + 今年累计 − 去年同期累计）。现金 = `CashAndCashEquivalentsAtCarryingValue` + 短期投资（`ShortTermInvestments` / `MarketableSecuritiesCurrent` / `AvailableForSaleSecuritiesDebtSecuritiesCurrent`）；债务 = `LongTermDebt`（含一年内到期），缺时 `LongTermDebtNoncurrent + LongTermDebtCurrent`、`…AndCapitalLeaseObligations` 或可转债科目，加 `ShortTermBorrowings`（没有时 `CommercialPaper`），不含经营租赁。股数 = dei `EntityCommonStockSharesOutstanding`（缺时最近一季稀释加权股数），与“市值 ÷ 股价”差超过 25% 时（多类股、ADR）用后者。20-F / 40-F 申报人和海外公司用 Yahoo 财务时间序列（约 4 个财年，总债务减租赁负债），股数用市值 ÷ 股价，报表币种与股价币种不同时按页面汇率换算营收和净现金。一致预期营收：Yahoo `earningsTrend` 的 `revenueEstimate`（0y、+1y，含分析师人数）。无风险利率：美国财政部每日收益率曲线 CSV 的 10 年期（失败时 FRED `DGS10`；都失败时页面要求手动填写）。
- FCF 折现：FCF = 经营现金流 − 资本开支；基准利润率 = 最近 3 个财年 FCF 利润率平均（周期环节 5 年）；基准起始增速 = 一致预期营收增速（≥ 3 家分析师；FY+1 vs FY0，或 FY0 vs 上一财年）→ 3 年营收 CAGR → TTM 同比，截断在 −10% ~ 40%；10 年内线性衰减到 gT，终值 = FCF₁₀ × (1 + gT) ÷ (r − gT)，股权价值 = EV + 净现金。r = 10 年期国债 + ERP（默认 5%）；gT 默认 2.5%，不超过无风险利率且比折现率低 0.5pt 以上。情景：r ±1pt、增速 ±|g0| × 30%、利润率 ±20%。反向 DCF：二分法求现价隐含的起始增速（−30% ~ 100%），以及基准增速下隐含的 FCF 利润率；FCF 利润率 ≤ 0 时只给“需要的 FCF 利润率”。敏感性：r ±2pt × gT ±1pt。
- 金融口径（`profile = financial`）：剩余收益法，合理市净率 = (ROE − gT) ÷ (r − gT)，ROE ±20%、r ∓1pt；反向给现价对应的 ROE。权益 REIT 不估值（需 FFO / AFFO）。
- FCF 利润率口径（参数“FCF 利润率口径”，默认“自动”；`config.json` `valuation.defaults.mbasis / ramp_n / ramp_t`）：近 3 年平均（原来的做法，周期环节 5 年）、最近财年、TTM、利润率爬坡。爬坡：m_t = m_start + (T − m_start) × min(t ÷ N, 1)，N 默认 5 年、稳态 T 默认 15%（**用户假设，不是数据得出**），之后不变，终值用第 10 年；m_start = TTM（可用时）否则最近财年；情景 Bear / Bull = T × (1 ∓ 20%)。
- 一次性收入粗筛（有 TTM 时，任一条）：TTM 营收 > 最近财年 × 1.5；一致预期营收 FY+1 vs FY0 < −30%；一致预期 EPS FY+1 < FY0 × 0.7（两期 > 0）；后两条两期都要 ≥ 3 家分析师。命中时 TTM 不用于自动口径和爬坡起点，卡里写“疑似一次性收入，未外推：…”；手动选 TTM 照用但提示。
- 自动口径按顺序：周期环节 → 多年平均（不用 TTM / 爬坡）；TTM 可用、高于近 3 年平均且 FY−2 < FY−1 < FY0 → TTM；近 3 年平均 ≤ 0 且最近财年利润率高于上一财年 → 爬坡；否则近 3 年平均。所选口径缺数据时回退到平均。卡里写明口径和原因，平均与 TTM 并列（相差 > 10pt 提示一次性因素），爬坡列出逐年利润率路径。
- 单独设定：每张评估卡可以给这家公司单独设口径和 N / T（存在同一个 localStorage 键的 `ov` 里，按代码），卡里标“本公司单独设定”；“恢复默认”只重置全局参数，“清除全部单独设定”另有按钮。
- FCF ≤ 0（只给需要的利润率）：平均 / 财年 / TTM 时 m0 ≤ 0，爬坡时 T ≤ 0。反向 DCF 在爬坡下固定路径求 g0，隐含利润率求“需要的稳态 FCF 利润率”。情景、敏感性、价格轴、PEG 筛选列和对比池列都用同一条利润率路径。
- Python 镜像：`radar/valuation.py` 的 `dcf_engine` / `dcf_reverse` / `ri_engine` / `margin_path` / `one_off_guard` / `choose_basis` / `dcf_prep` / `dcf_case` / `dcf_entry` 与页面逐行对应（默认参数 `default_params`），两边改动必须同步。
- 局限：对折现率和永续增速非常敏感；利润率用历史平均、TTM 或假设的爬坡外推，商业模式、资本开支周期变化或一次性现金流（预收、回款、资本开支推迟）时误差大；一次性收入识别是规则粗筛，会漏判也会误判；股权激励没有扣除；一年的一致预期被当作 10 年路径的起点；没有回测。

**全市场速查与价值通道（`python -m radar quality`，`radar/quality.py`，只展示，不计分）**

- 全市场速查（页面最上方，左侧“公司快速跳转”也会搜到）：全市场热度快照里每家有可比季度营收、有代码的美股公司（约 3400 家）都能查到，显示 SIC 行业、TTM 营收、最新季度同比、毛利率、营业利润率，以及没进入行业成长筛选的原因（不属于已配置环节、增速不在门槛内、规模不在范围、上年基数太小、排除规则、交易所 / 市值 / 行情），用页面同一套 classify 规则重算；同时说明是否在价值通道、不在时没过的门槛。
- 价值通道（PEG 筛选之后）：和行业成长筛选并列的第二个入口，不要求高增长。SEC XBRL frames 取全部报送公司 5 个财年（按日历年对齐）：最近财年营收 ≥ 2 亿美元且盈利；ROE（净利润 ÷ 年初年末平均股东权益，权益 ≤ 0 的年份不算）至少 4 年可算、中位数 ≥ 12%、最低 ≥ 5%；自由现金流（经营现金流 − 资本开支）为正 ≥ 4 年；5 年经营现金流合计 / 净利润合计 ≥ 0.8；营收不收缩；净负债 ≤ 4 年平均自由现金流（不用负债 / 权益：大量回购会压低账面权益）；Nasdaq / NYSE 上市；非金融（SIC 60–67 未覆盖）。通过的公司按通道内 6 项百分位等权排序：ROE 中位数、最低 ROE、现金转化、FCF 收益率、盈利收益率、股东回报率（分红 + 回购，回购为总额、未扣股权激励）；周期（SIC 10/12/13/29/33/44 或所在环节为周期）只列出不排名。另列“现价隐含增速 vs 过去 4 年营收复合增速”（同一套现金流估值引擎反推），只描述现价包含的假设，不进入得分。收益率 > 25% 标“先核实”，商誉超过权益 + 有息负债一半标“商誉高”。排序没有回测，不是买卖建议；不进入评分、因子、结论、PEG 分层和对比池评分。
- 金融口径（价值通道“口径”切换；SIC 60–67，不含 REIT 6798、SPAC 6770、投资基金 6726）：不看自由现金流和负债（存款、保险浮存金就是业务），门槛为股东权益 ≥ 10 亿美元、最近财年盈利且 5 年中 ≥ 4 年盈利、ROE 中位数 ≥ 10% 且最低 ≥ 4%、股东权益 4 年不缩水。通道内按 ROE 中位数、最低 ROE、权益增速、盈利收益率、股东回报率、市净率（越低越好）6 项百分位等权排序；“现价隐含 ROE”按剩余收益法稳态 P/B = (ROE − g) ÷ (r − g) 反推（r = 国债 + 5%），与 5 年 ROE 中位数对比，只展示。
- 简化评估卡（价值通道每行“展开”，速查里“打开简化评估卡”）：门槛逐条、五个财年明细（营收、净利润、经营现金流、资本开支、自由现金流、分红、回购、年末权益、ROE）、估值收益率与反推结果、最新一季变化、人工核实清单、SEC 10-K 与 Yahoo 链接。不在行业筛选里的公司也能“＋对比”：对比池里分成“价值通道”和“价值通道 · 金融”两组，只用通道的六个维度在组内等权比较（不受维度权重设置影响），CSV 另附 vc_* 列。

**交集 · 成长 × 价值 × 现价低于估值（页面“交集”分节，美股和 A 股都有，纯前端）**

- 同时满足：在行业成长筛选里（A 股为 ② 新兴筛选）、在价值通道里、按当前“估值参数”算出的基准每股价值高于现价至少所选比例（0 / 15 / 30 / 50%，默认 15%；美股金融口径用剩余收益法）。数字与评估卡、对比池的现金流估值一致，改参数后自动重算。
- 默认排除周期（可勾选包含）；A 股另默认排除“交易驱动”和“近期下滑”；可隐藏差距 > 200% 的公司（多半是默认假设不适用）。提示列标出差距过大、周期、商誉高、ROE 极高（回购压低权益）、近期营收下滑、风险门禁、疑似一次性收入。可按估值差距、价值通道排名或 ROE 排序，每行可打开评估卡和“＋对比”。只缩小研究范围，规则没有回测，不是买卖建议。

**估值台账（`python -m radar ledger`）**

- 作用：每次运行按**默认参数**给每家美股公司（按代码去重，取页面里第一条评估口径；金融口径用剩余收益法）记一笔：股价、Bear / Base / Bull、相对现价、隐含增速 / 隐含 FCF 利润率 / 隐含 ROE、R0、m0 与口径、g0 与来源、净现金、股数、rf / ERP / gT、一致预期增速与家数、目标价中位数、52 周高低。用来对比“数据变化带来的估值变化”；不是目标价，不是买卖建议，方法未回测；不进评分。
- 文件：`data/ledger/us_ledger.jsonl`（只在本地，`data/` 不提交；**只追加**，已有行不改不删）和 `data/ledger/us_ledger_meta.json`（运行索引）。同一份（估值文件 + 行情快照）对同一代码只记一次，重复运行追加 0 条。不从旧快照补历史。被替换的台账不删除，移到 `data/ledger/archive/`（如 FCF 利润率口径上线前用旧算法写的 `us_ledger_pre_basis_<时间>.jsonl`），页面不读归档。
- 算法：每条记录都由 `radar/valuation.py` 的 `dcf_entry`（`dcf_prep` + `dcf_case`，`default_params`）算出，即页面估值引擎的 Python 镜像（含 FCF 利润率口径 auto / avg3 / fy / ttm / ramp 和一次性收入规则）；`radar/ledger.py` 没有自己的估值引擎。记录字段：日期、股价、Bear / Base / Bull、相对现价、估值方式（ok / negfcf / ri / na + 原因）、口径与原因、一次性收入命中项、爬坡 m_start / T / N、m0、近 3 年平均与 TTM 利润率、R0、g0 与来源、净现金、股数、rf / ERP / gT、隐含增速、隐含 FCF 利润率（爬坡时为需要的稳态 T）、一致预期增速与家数、目标价中位数、52 周高低。
- 本期 vs 上期（`chg`，相对该代码的上一条记录，在记账时算好）：股价、基准估值、相对现价（pp）、隐含增速（pp）、一致预期增速（pp）与分析师家数、目标价中位数、口径切换。基准估值变化的归因用依次替换法，固定顺序：① 营收基数 R0 → ② FCF 利润率路径（m0 / 口径 / 爬坡起点）→ ③ 起始增速 g0 → ④ 净现金与股数 → ⑤ 参数 rf / ERP / gT / 爬坡 N、T；每步把一组输入从上期换成本期、用 `valuation.dcf_engine` 重算基准情景，估值差就是该项贡献（占上期基准估值的百分点），各项相加正好等于总变化。交互影响落在靠后的一项，**顺序不同拆分会不同**。金融口径：ROE → 每股净资产 → 参数。FCF ≤ 0 的公司跟踪“需要的 FCF 利润率”的变化；前后估值方式不同（如 FCF ≤ 0 → 三情景）时不做归因，只说明方式变化。
- 结论句（只陈述数字）：最大的驱动项（第二项超过总变化 1/3 时也列出）、股价变化、相对现价和隐含增速的变化；标签：基本面驱动（估值变化大于股价变化且 R0 / m0 / g0 贡献过半）、价格驱动（股价变化 ≥ 2% 而估值变化 < 2%）、参数驱动（利率参数贡献过半）、基本不变。只有一条记录时显示“首次记录（日期），下次更新后显示变化”。阈值在 `config.json` 的 `valuation.ledger`。
- 页面：评估卡“现金流估值”里的“估值台账”（最新结论、股价 vs 基准估值走势和 Bear–Bull 区间、逐期记录表；台账固定用默认参数，上方实时估值按当前参数）和全局“估值台账 · 本期变化”（上调 / 下调 / 基本不变计数，按估值变化、相对现价变化、隐含增速变化排的前 15 名，带归因条，点代码跳到评估卡），对比池有“台账：本期变化”列（只展示）。页面最多嵌入每家最近 26 条。
- 规则标签（`radar/ledger.py` 的 `tags()`，记账时算好存进记录的 `tags`；页面的 `ldgTags` 用同一规则从台账记录重算，所以加标签前写的老记录也有标签，已有行不改写；两边必须保持一致）。阈值在 `config.json` 的 `valuation.ledger.tags`：
  - 变化幅度（需要上一期）：基准估值变化 ≥ +15% 大幅上调、+5~+15% 上调、±2~5% 小幅变化、< 2% 基本不变、−5~−15% 下调、≤ −15% 大幅下调；FCF ≤ 0 的公司看需要的 FCF 利润率变化（2 / 5pt）：需要利润率（大幅）上升 / 下降。
  - 估值位置（本期，只看三情景 / 剩余收益）：基准 / 现价 − 1 ≥ +50% 现价远低于基准、+15~+50% 现价低于基准、±15% 接近基准、−15~−50% 现价高于基准、≤ −50% 现价远高于基准；另有 现价低于熊情景 / 现价高于牛情景。
  - 组合（需要上一期）：基本面改善·价格未跟（估值 ≥ +5% 且股价 ≤ +2%）、价格先行（股价 ≥ +10% 且估值 ≤ +2%）、基本面转弱（估值 ≤ −5% 且 R0 / m0 / g0（金融：ROE / 每股净资产）贡献过半）、预期上修 / 下修（一致预期增速 ±3pt）、差距收窄 / 扩大（|基准相对现价| 向 0 靠近 / 远离 ≥ 10pt）、口径切换。
  - 注意（本期）：一次性收入、增速截断、爬坡假设、周期、估值≤0。
  - 标签按固定阈值机械生成，描述模型输出和数据变化，不是买卖信号；方法未回测。
- 筛选（页面“估值台账 · 本期变化”顶部，纯前端，保存在本标签页的 sessionStorage）：搜索（代码 / 公司名）、行业、类型、估值方式、FCF 口径（含周期）、标签（同组任一、跨组同时满足）、只看对比池、估值位置区间（Base vs 现价 %）、变化方向（只有一期时不可用）。“全部公司”表按筛选显示（n / N 家，各数值列可排序，点代码打开评估卡），三张变化最大表也按筛选；顶部计数句仍按整期统计。评估卡台账和对比池“台账：本期变化”列显示同样的标签。
- 前向跟踪（`python -m radar forward`，`radar/forward.py`；页面在“估值台账”下方，构建时计算，只嵌入汇总）：每条台账记录是一个起点，记下当时的标签（按当前阈值从该条记录重算，只用到这条记录和它与上一条的变化，不含之后的信息）和股价；之后的台账记录到了第 1 / 4 / 13 / 26 / 52 周（允许 −2 天到 +max(5 天, 25%) 的窗口），算股价涨跌，再减去同一起点全部公司涨跌的中位数（相对全样本，等权）；同行业 ≥ 5 家时另算相对同行业；另列 SPY 同期涨跌（取最新快照的 1 年日线）。按标签和期限汇总：样本、公司、起点数、涨跌中位数、相对全样本 / 同行业中位数、高于同期中位数的比例、25%~75%；起点 < 4 个或公司 < 20 家标“样本不足”。股价不含分红、未复权；前后股数变化超过 25%（疑似拆股 / 增发）的样本剔除并计数。**不回填历史**（过去的估值无法不用今天的财报重算），所以 1 周的样本最早在第二次台账之后出现，52 周要一年。样本重叠、不独立，未做显著性检验，同时比较很多标签和期限会有偶然差异；只描述发生了什么，不说明规则有效，不是买卖信号，不会自动调整阈值。完整样本写在 `data/ledger/us_forward.json`；参数可在 `config.json` 的 `valuation.ledger.forward` 覆盖。
- 每周顺序：`fetch` → `valuation` → `ledger`（`ledger` 结束时会重新生成页面）→ `forward`（写审计文件）。

**金融类评估口径**

券商、交易所、交易平台和放贷公司没有毛利，经常没有营业利润科目，资产负债表上的现金大多是客户资金，估值看市盈率、市净率和 ROE，放贷公司的主要风险是信用损失。所以环节可以在 `sectors.json` 里设 `"profile": "financial"`（默认 `standard`），这类环节换一套规则：

- 数据：营收按 `config.json` 里 `financial_tags.revenue` 的顺序取（`RevenuesNetOfInterestExpense` → `Revenues` → 合同收入；券商和放贷公司的合同收入通常只含手续费），另取税前利润、股东权益、信用损失拨备（`ProvisionForLoanLossesExpensed`、`FinancingReceivableExcludingAccruedInterestCreditLossExpenseReversal` 等）和净利息收入。这些只用于金融类环节，其他行业的数据和结果不变。金融类龙头的这几项来自 Yahoo 财务时间序列。
- 林奇清单：增长、盈利能力（税前利润率及变化）、ROE（TTM 净利润 / 平均股东权益）、估值（市盈率、市净率、PEG）、资本（股东权益同比）、信用成本（只对 `"credit": true` 的放贷环节：拨备占收入及变化）、周期性提示、稀释、内部人、财报 vs 预期、关注度。不看毛利率和现金跑道。
- 研究优先池门槛：周期性环节不剔除、只提示；用"TTM 净亏损"代替"亏损且现金不足 6 个季度"；股东权益为负剔除；缺市值、稀释超过 50%、营收同比超过 300% 照旧。
- 排序因子：增速、加速、税前利润率、税前利润率趋势、ROE、PEG（没有可靠的 PEG 时用市净率）、股东权益增长、稀释、内部人、关注度、EPS 超预期；百分位只在同一口径的公司之间计算。
- 已知局限：拨备超过收入的视为标签错误不使用；按公允价值计量贷款的公司（如 Upstart）XBRL 里没有拨备科目；6 月财年的公司（如 Affirm）第四财季只在年报里，SEC 季度数据缺这一季；有大量少数股东权益的公司（如 IBKR）归母净利润、股东权益与市值口径不一致，市盈率和市净率需要回到原始财报核对。

**自动生成的文字**

- 机会、风险、买入理由、不买的理由、结论：按数据规则生成，见 `radar/score.py`。
- 一句话介绍：优先用 `config/notes.json` 里你写的描述，其次是 `config/profiles_zh.json` 中的中文概述，都没有时显示 Yahoo 英文业务描述的首句。

## 已知局限

- SIC 和 Yahoo 行业分类都很粗，归类需要人工复核。
- 同一家公司可能同时出现在两个行业。
- 海外公司没有内部人交易数据；免费数据里没有营收的历史预期，所以"财报 vs 预期"只比较 EPS。
- XBRL 和 Yahoo 偶有数据错误，异常值以公司原始财报为准。
